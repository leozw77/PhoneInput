# PhoneInput 当前实现状态

更新时间：2026-08-06
当前稳定版本：`v1.2.5`
稳定分支：`stable/v1.2.5`

## 1. 项目定位

PhoneInput 是一个 Windows 托盘程序。手机不需要安装 App，只要与电脑连接同一个 Wi-Fi，即可通过手机浏览器向 Windows 当前输入控件发送文字、按键和选区操作。

程序使用本地局域网通信，不依赖账号、云服务或服务器中转。

## 2. 当前已实现功能

### 手机输入

- 支持批量输入：手机编辑完成后一次性发送。
- 支持实时输入：中文输入法确认、英文字符、删除和选区变化可以实时同步。
- 支持中文、Unicode 和 Emoji。
- 支持插入、替换、删除、剪切和拖动删除。
- 支持手机光标与电脑输入控件选区同步。
- 支持 UTF-16 位置与 Windows Unicode 字符位置之间的转换。
- 支持普通回车提交。
- 支持 `Shift+Enter` 换行而不提交。
- 支持速度调节和逐字符发送延迟。
- 支持手机端快捷触发 Windows 截图工具：`Win+Shift+S`。

### Windows 目标窗口

- 自动识别当前前台窗口和当前获得键盘焦点的输入控件。
- 支持从手机端显式切换到已经打开的：
  - ChatGPT Desktop
  - Google Chrome
  - 微信
- 窗口切换不会自动启动目标程序。
- 每个目标窗口保存独立的手机草稿、光标位置和控件标识。
- 切换回已识别的目标窗口时，可以恢复对应草稿和光标状态。
- 不会自动从普通浏览器页面、地址栏或文件资源管理器路径栏导入文本。

### 桌面内容回读

- 使用 Windows UI Automation 读取支持的输入控件内容和选区。
- 支持读取当前控件的文本、光标位置和选区范围。
- 只在目标窗口和焦点控件仍然匹配时应用回读结果。
- 支持显式手动同步。
- ChatGPT Desktop 的 `Do anything` 空编辑器占位文字会被识别为空内容。
- 自动切换到空的 ChatGPT Desktop 输入框时，手机输入框会清空。
- 会拒绝 Chromium 页面根节点等不适合作为输入内容的文本。
- Google Chrome 搜索框目前只保留精确控件识别和手动读取路径；后续完整回读功能尚未继续处理。

### 稳定性和竞态保护

- 目标锁定从手机产生真实输入后才开始，空输入不会控制电脑焦点。
- 空手机输入不会发送无意义的光标或选区按键。
- 输入、按键和选区队列会校验目标窗口是否仍然一致。
- 目标窗口在异步操作期间发生变化时，会终止本次操作，避免输入发送到错误程序。
- 回读请求会校验请求目标、当前前台窗口和焦点控件，防止过期结果覆盖手机状态。
- 使用单实例锁，普通权限和管理员权限启动也不会留下重复的端口占用实例。
- 程序只运行在系统托盘，不弹出常驻桌面主窗口。

### 连接和用户界面

- 默认局域网端口：`51876`。
- 提供手机网页、Web App manifest、Service Worker 和图标资源。
- 提供二维码窗口，显示当前局域网连接地址。
- 支持 Android/iPhone 主屏幕快捷方式元数据。
- 支持 Windows 开机启动设置。
- 支持手机端显示当前电脑目标窗口和连接状态。
- 支持手机端操作提示和错误提示。

### 日志和诊断

- 提供有界的异步诊断日志。
- 记录窗口激活、目标窗口、焦点控件、读取来源、重试状态和失败原因。
- 默认不记录用户输入的实际文本，只记录文本长度等必要诊断信息。
- 目标不匹配、控件不支持、读取失败等情况会返回明确原因。

当前正式使用的是 framework-dependent 包：

`Release/v1.2.5-framework-dependent/PhoneInputEnhanced-Windows-x64.zip`

包内只包含：

- `PhoneInputEnhanced.exe`
- `web.config`

目标电脑需要预先安装 .NET 8 Desktop Runtime。项目保持 `SelfContained=false`，发布命令使用 `--self-contained false`，不会把 .NET Runtime 打进 ZIP。

旧的自包含目录 `Release/v1.2.5` 已清理，不应继续使用。

## 5. 当前限制

- 程序只能向当前拥有键盘焦点且受支持的 Windows 控件注入输入。
- 普通权限程序不能向管理员权限程序注入输入。
- Windows 登录界面、安全桌面、部分游戏和安全输入框会拒绝模拟输入。
- 富文本编辑器对 `Ctrl+Home`、选区和 Emoji 边界的处理可能不同。
- 用户直接在电脑上移动光标或修改文本后，手机端预期位置可能暂时与电脑实际位置不同。
- 电脑重新连接 Wi-Fi 后局域网 IP 可能变化，需要重新扫描二维码。
- Chrome/Google 搜索框完整自动回读仍未完成。

## 6. 后续开发规则

- 后续新功能应从 `stable/v1.2.5` 新建独立分支。
- 不覆盖稳定发布目录和稳定 tag。
- 新包必须使用 framework-dependent 发布方式。
- 必须验证实际启动、局域网访问和真实输入回归后，才能视为可用发布包。
